这就是你现在打开的网站。它是一套基于 Jekyll 的个人站点模版，也是我自己长期用的壳：把「我是谁 / 做过什么 / 正式写过什么 / 随手记下什么」放进同一套导航里，而不是做成四个互不相干的页面皮肤。

个人站常见的问题不是缺页面，而是缺**稳定的找路方式**。简介、作品、长文、碎片笔记的浏览节奏完全不同——作品要一眼扫过，文章要按主题与年份回看，笔记要随时跳进跳进；若每换一类内容就换一套布局，读者会先迷路，作者也会越改越散。

这套模版的目标很具体：在桌面端给出接近飞书文档 / 知识库的「工作台」体验——分区清楚、目录常在、正文居中可读；在窄屏上再诚实降级，不硬撑三列。

## 布局上为什么这样拆

整体是 **左栏（rail）→ 中栏（catalog / 可替换侧栏）→ 正文（main）**。三列不是为了看起来复杂，而是把三种不同频次的动作拆开：

1. **换内容分区**（低频、全局）
2. **在分区里找下一篇 / 筛一类**（中频、列表）
3. **读当前这篇**（高频、专注）

### 左栏：只负责「我在哪一类」

左栏固定约 88px，图标 + 短文案纵向排列，入口由 `_data/rail.yml` 配置（本站默认是动态、作品、文章、笔记）。

它故意做得窄、且 `position: fixed`：滚动正文、甚至触控板过顶回弹时，分区入口始终钉在视口左侧，读者不用先滚回页顶再找导航。选中项左侧有一条强调色竖条，视觉上「指向」中栏——提醒你：左栏定分区，真正的列表在下一列。

这里不放站点大标题、不堆社交链接，是为了避免和个人品牌页抢第一眼；个人站的「我是谁」放在首页正文里讲更合适。

### 中栏：跟着分区走的目录，而不是全局侧栏

中栏默认是当前分区的目录：进文章就列文章，进笔记就列笔记，进作品就列作品。读某一篇时，同栏还能跳到兄弟篇，而不必退回列表页再点一次。

这是相对传统博客侧栏最大的差异：**中栏内容与左栏入口联动**，而不是全站挂同一套「最新文章 / 标签云」。个人站内容异构时，全局侧栏往往既占宽又帮不上忙。

中栏还可以换成别的职责（同一套壳、不同任务）：

- 列表页用标签侧栏做筛选
- 部分页用广告位做变现
- 默认仍是目录

宽度可拖拽（约 220–480px），偏好会记在本地；左栏底部一键收起中栏，给「只想专心读」留出整屏。实现上中栏覆盖在正文左侧留白上，**不挤压**正文的居中与最大宽度——目录出现时，阅读栏位置尽量稳定，减少「侧栏一开字就跳」的感觉。

### 正文：有限行宽的文档画布

正文最大宽度约 820px，白底画布，标题用衬线、正文字体用系统无衬线，强调色是靛紫。视觉上参考文档产品，而不是再套一层博客主题的顶栏、底栏、多色模块。

目的只有一个：**长文读得下去**。装饰让位于行宽、字重与留白；链接与当前位置用强调色，选中高亮刻意不用大块强调色铺底，避免和「你在哪」抢同一语义。

宽屏（约 1400px 以上）且文内有目录时，再在右侧浮一层 TOC，跟着滚动高亮——只在真有空间时出现，中等宽度不硬塞第四列。

### 不同内容，不同列表形态

壳是统一的，列表形态按内容目的分开：

| 内容 | 列表怎么呈现 | 原因 |
| --- | --- | --- |
| 作品 | 卡片网格 + 详情页 | 产品需要封面感与状态（运营中 / 类型），适合扫视 |
| 文章 / 笔记 | 标签云 + 按年归档 | 写作量大、要按时序与主题回找；支持 hash 深链到标签 |
| 首页动态 | 经历、自评与近期条目 | 回答「这人是谁、最近在忙什么」 |

文章与笔记共用标签与归档组件，但 collection 与 permalink 分开，避免「正式成文」和「随手笔记」混在同一个时间河里分不清权重。

### 窄屏怎么退

三列是桌面假设。宽度不够时：

- 中等屏：先拿掉中栏（以及收起按钮），把筛选能力交给页面内的标签条
- 手机宽：左栏改成顶部横向导航，正文单列

也就是：**信息架构保留，空间不够就减栏，不改成另一套完全陌生的站点**。

## 模版里还固定了什么

- **改资料多于改代码**：姓名与站点信息在 `_config.yml`，左栏在 `rail.yml`，经历在 `experience.yml`，作品 / 文章 / 笔记各进各的目录。
- **静态可托管**：Jekyll 构建后可上 GitHub Pages 或任意静态托管；本站即按此运行。
- **阅读相关交互**：目录滚动位置记忆、中栏宽度记忆、分区切换与同栏换篇的历史栈策略、宽屏 TOC 等，都写在同一套前端脚本里，避免每页各搞一套。

## 我的角色

产品定位、信息架构、视觉与前端实现都是自己做的；本站是第一处完整落地，并会继续当「狗粮」迭代。

若你也需要一个偏工作台、而不是杂志封面风的个人站壳，可以直接把这套结构当起点——先定左栏有几类内容，再决定中栏在每一类里该列什么。
